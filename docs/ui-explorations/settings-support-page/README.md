# 设置页里的赞助页 · 方向对比（第 01 轮）

## 任务

在 Dayline（Obsidian 日历 / 日记插件）的设置页里放一页赞助。它不是落地页，也不是支付流程，而是用户改设置时顺路会看到的一块地方。

- **用户**：已经在用 Dayline 的人，正在设置里找别的东西，桌面端为主。
- **主动作**：看清楚"这是自愿的、不锁功能"，然后决定要不要扫码。
- **这一页要回答的问题**：钱去哪了？不给会怎样？除了钱还能做什么？
- **约束**：只能在设置页里；只有一个真实渠道（微信赞赏码）；不能伪造金额、支持人数或感谢名单；不能挡住设置本身。

## 共用的事实

三个候选写的是同一组事实，只有语气和版式不同：

- 插件叫 Dayline Journal，MIT 许可，作者 Haoo，当前 v2.10.1。
- 免费、无账号、日记只存在用户自己的库里。
- 唯一渠道是 README 里那张微信赞赏码（`assets/readme/sponsor-wechat.jpg`，二维码中心就是那只猫）。
- 赞赏不解锁任何功能，也不影响功能怎么排期。
- 不花钱的替代路径：star、反馈问题、推荐给别人。

## 三个方向

### 01 一行 · `a.html`
- **北极星**：赞助应该像设置里的一项——需要时找得到，不需要时看不见。整页唯一带颜色的东西是二维码本身。
- **生成引擎**：设置页自己的语法（借用系统设置里"关于 / 更新"那一类行的形状），不另造一套。
- **骨架**：单列设置行。分区标题「支持」→ 关于这一行 → 赞赏这一行，点开后内容在行下方长出一块。用户来这页是改设置，赞助排在最后。
- **字体**：系统 UI 无衬线；行名 14/500，说明 13/1.62，分区标题 15/600。
- **色彩**：纯灰阶 `#ffffff` / `#1f2329` / `#6b7078` / `#e6e8ed`，一个彩色像素都不给，颜色留给二维码。
- **主视觉**：没有图。二维码 152px 放在浅灰抽屉里，是页面上唯一的图像。
- **控件语法**：与 Obsidian 一致——6–8px 圆角、1px 灰描边、白底按钮。
- **记忆点**：「收起」那一行。展开与收起的动作本身，就是这页唯一的表现。
- **放弃**：大标题、口号、进度条、感谢名单、任何动效。

### 02 一封信 · `b.html`
- **北极星**：把「要钱」写成「交代」——钱去哪、为什么，以及不打钱能做什么。
- **生成引擎**：信笺 × 一张回执。纸、墨、一枚可以撕下来的收据。
- **骨架**：单列文档，560px 行宽。返回 → 标题 → 两段话 → 回执 → 「不打钱，也能帮上忙」→ 一句声明。
- **字体**：宋体标题 29/600（`Songti SC`），正文系统无衬线 14.5/1.92，落款宋体斜体。
- **色彩**：纸 `#f7f1e6`、墨 `#2a211b`、朱 `#b6432c`、齿孔 `#e0d0b8`。
- **主视觉**：那张回执。二维码像贴在信上的小票，顶部是撕口，底部是落款。
- **图标**：一个都不用，用 01/02/03 和细横线代替。
- **控件语法**：2–4px 圆角、1px 墨线、几乎不用底色，动作都是文字。
- **记忆点**：回执上那行「— Haoo，和那只猫」。
- **放弃**：卡片网格、渐变、图标墙、任何催促语气。

### 03 深夜书桌 · `c.html`
- **北极星**：这页不像支付页，像深夜书桌的一角——台灯亮着，二维码是桌上的一张卡片。
- **生成引擎**：一个具体场景（深夜写字的那张桌子，一盏暖光台灯）+ 角色原型（猫）。
- **骨架**：双栏。左侧陈述 + 三行"赞赏会变成"的账本；右下是一张压在桌面上的实体卡片，左上空、右下重。
- **字体**：系统无衬线大标题 32/700、字距 -0.012em；正文 14/1.95；金额用 Menlo 等宽。
- **色彩**：夜 `#0f1512`、字 `#f2efe6`、灯 `#e8b15c`、次 `#a9b4ab`。
- **主视觉**：那片椭圆暖光、卡片和它的接触阴影。
- **图标**：不用图标，用光。
- **控件语法**：4px 圆角、纸卡旋转 -1.6deg、唯一的"按钮"就是那张卡片。
- **记忆点**：卡片压在桌上的那圈影子，和落在它身上的光。
- **放弃**：列表、表格、进度条、感谢名单、任何促销句式。

## 差异检验

- **比线框**：A 是横向行的堆叠；B 是单列竖读；C 是左文右物的对角块面。三个首屏的明暗块面分布不同，眯眼也分得开。
- **四项至多一项相同**：A 与 B 只共用"真实二维码"这一件素材，骨架、字体、色彩都不同；B 与 C 共用同一张二维码，但一个在回执上、一个在灯下的实体卡片上。
- **不按明暗分方向**：三个方向各有自己的材质感——系统灰、纸、夜与灯。明暗是材质的结果，不是分组依据。
- **至少一个走到极端**：03 深夜书桌（整页深色、实体卡片、光斑）。
- **至少一个打破品类套路**：02 和 03 都不是"设置行 + 二维码"这个默认做法；01 是刻意保留它。
- **不撞脸**：没有照搬任何见过的赞助页；01 沿用 Obsidian 基线，不算撞脸。

## 推荐

**先做 02 一封信。** 它在一屏里把赞助页该交代的三件事都交代完了：钱去哪、不锁功能、不打钱能做什么。而且它读起来是一封信，不是一张催款单——设置页里放这个，用户的防御心最低。

- **01 一行**是最稳的保底：实现最便宜、最像原生，但也最容易被滑过去。适合当"入口"，而不是全部内容。
- **03 深夜书桌**最有记忆点，和"日记"这件事的关系也最紧，但整页深色在浅色主题里是一块很重的色块，需要再做一版浅色主题的翻译。

如果想把两者合起来（设置行入口 → 一封信），先做一张合起来的首屏给用户确认，再动完整页面。

## 选择记录（2026-10-27）

用户选定 **01 一行**：侵入性最小、改动小。

文案改动：删掉"不想花钱？在仓库点一个 star，一样是帮忙。打开 GitHub 仓库"，换成一句"或者可以点个 star～"，并把它从区块下方移进抽屉里、二维码说明的最后一行——扫码和点 star 是同一时刻的两个选择，不该分两处。

第二轮（同日）：抽屉改成默认展开；补上「关于 Dayline」行和「检查更新」按钮。默认展开之后，这一块从"藏起来的一行"变成"打开设置滚到底就能看见的一小段"，收起的开关仍然保留。

第三轮（同日）：两处纠错。①「检查更新」原来打的是 api.github.com，换成 Obsidian 商店用的 community-plugin-stats.json——插件已经上架，商店那份版本表才是"能装到的版本"，而且走 raw CDN，比 API 好连。② 按钮原来是手搓的边框样式，和设置页里其它按钮不是一家；两行改成 Obsidian 自己的 setting-item 结构，按钮不带任何自定义样式，主题怎么渲染就怎么渲染。

## 已实现（2026-10-27）

按 01 落进插件，不是另做一张图：

- `src/settings-support.ts`：整块 DOM（关于行 + 咖啡行 + 抽屉 + 开关），默认展开，开关同时管 `aria-expanded`、文案和图标方向；「检查更新」按钮在检查期间禁用并显示"检查中…"。
- `src/plugin-update-check.ts`：读商店的 community-plugin-stats.json，从 dayline-journal 那条里挑最新的版本键（2.10.0 大于 2.9.4，按数字不按字符串），再和当前版本比；失败一律返回结果而不抛异常。通知由设置页负责，这个模块不依赖 Obsidian。版本表约 630 KB（解压 2.8 MB），缓存 10 分钟，重复点击不再联网；requestUrl 没有超时，这里 15 秒放弃并报"超时"，避免按钮一直停在"检查中…"。
- `src/settings-tab.ts`：`createTab` 之后多出一个 `support` 分区；`SETTINGS_SECTION_IDS` 与分区标题表同步。
- `src/i18n.ts`：10 条文案 × 9 种语言（分区名 + 行名/说明 + 抽屉四行 + 展开/收起）。
- `assets/sponsor-wechat.jpg`：从 600px 原图裁到二维码本体（340px），经 `dataurl` loader 内联进 `main.js`，插件目录仍然只有 `main.js` + `styles.css`。
- `styles.css`：全部走 Obsidian 变量，浅色/深色同一份；窄屏改为上下堆叠，粗指针设备开关 44px。

「检查更新」不会真的触发商店更新——Obsidian 没给插件这个接口。它只回答"有没有新版"，然后提示去「设置 → 第三方插件」更新。代价是每次点都要下一份商店的版本表，换来和商店一致的答案。

验证：`typecheck`、941 个测试、`build` 全过；Sandbox 里重新加载后 `dev:errors` 无报错，实际渲染出的设置页八个分区齐全，抽屉默认收起、点击后变成"收起"，二维码是内联 data URL。

## 落地时要注意

- 现在这三张图用的是写死的颜色。真正落地要换回 Obsidian 的变量（`--background-primary`、`--text-normal`、`--background-modifier-border` 等），并给深色主题各写一份对应关系。
- 文案要进 `src/i18n.ts`（中英各一份），不能直接写在 `settings-tab.ts` 里。
- 二维码现在是 `assets/readme/sponsor-wechat.jpg`，只在 README 里用；要让设置页显示，得让它进构建（esbuild 的 asset / data URL loader），或改成插件目录下的静态资源。
- 03 里的 15 / 9 / 30 是示意金额，真实页面要么去掉，要么换成作者确认过的说法。

## 说明与未做

- 本轮是方向探索：每个方向只有一张首屏、一个视口（1240×820 的 Obsidian 设置窗口），没有交互、响应式和动效；按流程不取证、不派评审。
- 三个候选共用的 Obsidian 外壳在 `frame.css` 里，只负责交代"这是在设置里"，不参与风格比较。
- 这一轮之后：选定方向 → 补完整状态（深色主题、窄屏、二维码加载失败、链接不可用）→ 接进 `settings-tab.ts`。
