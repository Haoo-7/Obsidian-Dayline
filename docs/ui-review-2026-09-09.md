# Dayline 前端审查与重构建议

日期：2026-09-09。范围：桌面月历、时间线、心情编辑及设置入口。

## 结论与证据边界

Dayline 有明确的产品特色：以真实照片和日期回看生活，心情是补充信息。粗糙感主要来自信息优先级和交互收尾不一致，而不是缺少装饰。不建议整套换肤，建议保留照片月历、主题变量和流体心情控件，重构其外围布局与状态。

本次为降级单上下文审查：两个独立审查 agent 均因服务 502 失败，由主 agent 完成源码和运行时核对。没有修改插件源码或日记。

- 运行环境：Main_Topic，Obsidian 1.13.7，Dayline 2.2.0，当前第三方浅色主题。运行包与未提交源码未做逐字节一致性验证，以下明确区分实测与源码判断。
- 通过 Obsidian CLI 和 Computer Use 检查运行时 DOM、计算样式、焦点和可访问性树。窗口截图始终返回旧画面，且 `document.visibilityState` 为 `hidden`，因此不以这些截图证明当前视觉效果。
- 仓库 `screenshots/dayline-showcase-filters.png` 仅用来理解历史布局；其中日期和当前源码已经不同，不当作当前缺陷证据。
- `detect.mjs --json src` 返回 `[]`。扫描器未报问题不等于界面合格，尤其本项目使用动态 DOM 和内嵌 CSS。
- 未注入浏览器覆盖层；未验证手机、深色主题或屏幕阅读器完整流程。外部规范页面检索未返回可用内容，不宣称完成 WCAG 合规检查。下文尺寸和动效时间是建议的项目规格。

## 优先问题

### P1：时间线丢失月份上下文

实测完整日期节点为 `display: none`。源码只展示星期和日号，列表没有月份分组；跨月浏览时“周三 9”无法单独确定日期。时间还取自 `modifiedAt || createdAt`，没有说明是修改时间，容易被理解为记录发生时间。

位置：`src/plugin.ts:2005`，`src/journal-timeline-view.ts:32`、`:435`、`:486`。

修复：按 `YYYY-MM` 分组并显示“2026 年 9 月”；每条保留完整日期的可访问名称。时间不可靠时不展示；展示文件时间时明确标注“更新于”，不要冒充事件时间。

### P1：筛选展开导致键盘焦点丢失

实测将焦点放在筛选按钮后触发点击，展开状态变为 `true`，但 `document.activeElement` 变成 `BODY`。原因是点击调用 `render()`，后者 `root.empty()` 删除了当前控件。月份跳转也使用相同整区重建方式，存在类似风险，尚未单独实测。

位置：`src/journal-timeline-view.ts:184`、`:273`；`src/plugin.ts:2777`。

修复：工具栏与筛选表单只创建一次，展开只改 `hidden` 和 `aria-expanded`；结果更新限定在列表、数量和已选条件。关闭浮层返回触发按钮；删除条件后聚焦邻近条件或筛选按钮。

### P1：心情未选择状态和默认值互相矛盾

实测第一步显示“选择一个强度”，但“继续”可用；直接继续后变为“平稳”，焦点直接落到“保存”。这把没有表达的感受隐式转成了一个有效值。日期输入框实测 `tabIndex === -1`，鼠标可用但正常 Tab 不可达。

位置：`src/mood-picker-modal.ts:90`、`:128`、`:245`。

修复：推荐未选择时禁用继续，第一次明确点击、拖动或键盘调整后启用。另一种可接受方案是从初始就明确显示“平稳”并使控件值为 0，但不能同时显示“请选择”。日期恢复 `tabIndex=0`，首次聚焦控制单独处理。第二步聚焦标题或首个感受选项，不默认聚焦提交。

### P1：编辑草稿没有完整的失败与离开路径

源码中标题保存失败会 `render()`，新输入内容没有恢复；索引推送也可能整区重建打断编辑。心情切换日期会覆盖当前 `score/labels/note`；保存时只禁用保存按钮，返回和日期仍可操作。自定义标签添加后重新渲染并再次聚焦保存按钮。以上是源码风险，未通过真实写入或故障注入验证。

位置：`src/journal-timeline-view.ts:531`；`src/mood-picker-modal.ts:144`、`:216`、`:249`。

修复：草稿独立于 DOM，编辑期间保留；失败显示就地错误和重试，不清空输入。日期切换按目标路径保存会话草稿。保存请求使用提交时快照并锁定会改变目标的操作；已有未保存内容时离开采用保留草稿或明确舍弃流程。

### P2：侧栏空间分配没有围绕阅读任务设计

当前运行时有图条目宽约 320px，正文列仅约 152px。源码在侧栏内仍固定使用 104px 缩略图，并以整个窗口 `@media (max-width: 420px)` 判断紧凑模式。大窗口里的窄侧栏不会触发该规则。

标题缺失时反复显示“添加标题”，把阅读列表变成待填写表单；日期 24px、摘要 12px、时间 10px，在有限空间内优先放大了日号而非正文。始终显示的连续记录统计进一步推迟列表起点。

位置：`src/plugin.ts:1992`、`:2004`、`:2017`、`:2020`、`:2108`；`src/journal-timeline-view.ts:453`。

修复：按面板容器宽度适配。默认摘要 13px、行高 1.5、日期 18–20px、次要信息 12px；窄侧栏缩略图 64–72px。没有标题时直接从摘要开始，编辑入口放到条目菜单和焦点可达操作中。统计默认一行摘要，详细趋势按需展开。

### P2：筛选的表单层级和统计范围不明确

日期字段有 `aria-label` 和 `title`，但没有可见的“开始/结束”标签；各类字段平铺排列，清除用孤立的 X。结果数量随筛选变化，统计仍取全部条目，用户可能认为它们属于同一范围。无结果只显示一句文字，无就地恢复操作。

位置：`src/journal-timeline-view.ts:218`、`:280`、`:335`、`:409`。

修复：日期范围独立成组，其他筛选使用带字段名的紧凑布局；激活条件显示数量及可单独移除的标签；明确“全部日记统计”，或让统计跟随筛选并标明范围。空结果提供清除筛选，空资料库提供创建日记/配置来源。

### P2：视觉语言和交互反馈不统一

源码中的心情弹窗使用径向渐变、整面随心情着色、彩色阴影、胶囊按钮；月历使用紧凑平面按钮。感受选中态主要靠淡色背景和阴影，识别不够直接。每次第二步重建都会重新触发 360ms 模糊入场动画。时间线焦点只改变右边框颜色，同时移除 outline。

位置：`src/plugin.ts:1999`、`:2024`、`:2050`、`:2080`。

修复：保留流体图形作为心情表达主体，外围恢复主题背景和标准按钮。选中标签增加勾选标志。焦点使用完整 2px 轮廓。按钮反馈建议 100–140ms，面板切换 160–200ms；不对每次更新播放整表动画。已有 reduced-motion 支持应保留。

### P2：普通设置暴露实现细节，本地化也有断口

Journal sources 要求手写 JSON，并在每次输入时解析和保存；编辑过程中暂时无效的 JSON 会弹 Notice。创建日记弹窗硬编码英文，中文环境仍显示英文。月历可访问名称里的 `entries`、`weather available` 同样硬编码。

位置：`src/settings-tab.ts:236`；`src/plugin.ts:2865`、`:4305`。

修复：来源使用文件夹选择、名称和日期字段组成的可编辑行，JSON 只放高级入口，显式应用后验证；错误显示在字段旁。所有用户可见与辅助技术文案进入 `i18n.ts`。

## 建议保留

- 月历中的真实图片是产品识别点，不需要新插画或装饰背景。
- 大多数界面已经使用 Obsidian 主题变量，图标沿用宿主 `setIcon`。
- 搜索输入当前使用局部 `updateResults()`，不是每次输入都重建工具栏；应推广这个模式。
- 流体控件已有键盘处理、状态播报及 reduced-motion 支持，不能笼统判定为“不支持无障碍”。
- 缩略图已有懒加载和过期请求保护，应在布局重构中保留。

## 重构方案

采用“保留产品特色，重整呈现与状态”的路线。仅换 CSS 无法解决焦点和草稿问题；迁移 React 或整套重写又没有必要。

1. 先修日期语义、筛选焦点、心情显式选择、编辑失败保留草稿。
2. 建立很小的样式基础：4/8/12/16px 间距、6px 控件圆角、最多 8px 条目圆角、主题背景/边框/文字变量。心情色仅用于图形、标记和选中反馈。
3. 时间线工具栏固定节点，结果列表按月分组；以面板容器查询控制缩略图和内容密度。
4. 心情编辑保持两步流程，补齐状态、日期草稿缓存、就地错误和焦点恢复。不要同时改存储契约。
5. 最后整理设置表单、空状态和中英文一致性。

### 心情草稿与提交状态

```ts
type MoodDraft = {
  filePath: string;
  score: number | null;
  labels: string[];
  note: string;
};
type MoodEditorState =
  | { status: 'editing'; step: 1 | 2; draft: MoodDraft }
  | { status: 'saving'; step: 2; draft: MoodDraft }
  | { status: 'error'; step: 2; draft: MoodDraft; message: string };
```

状态规则：

| 操作 | 状态变化 | 用户反馈 |
|---|---|---|
| 未选择心情 | `editing`，score 为 null | 继续禁用，不暗中默认值 |
| 明确选择 | score 为 -2 到 2 | 图形、文字及继续同步更新 |
| 继续 | step 1 → 2 | 聚焦步骤标题或首个感受 |
| 添加自定义标签 | 只更新标签区域 | 保持输入焦点，不重播整页动画 |
| 切换日期 | 按 filePath 缓存/恢复 draft | 切换前后草稿可找回 |
| 保存 | 快照 → saving | 显示“保存中”，锁定重复提交和目标切换 |
| 保存失败 | saving → error | 保留草稿、就地错误、重试 |
| 保存成功 | 关闭并刷新对应条目 | 焦点返回发起编辑的条目/按钮 |
| Escape | 根据 dirty 与 saving 状态处理 | 不把尚未提交的草稿无声清空 |

不需要引入状态机库。用上述联合类型或等价的小型控制器集中控制按钮、离开和提交分支即可。保存回调必须拿快照，不能在异步完成后再读已经切换的日期。

## 验收

- 月份切换、过滤条件删除、后台索引更新后，焦点及正在输入的草稿不丢失。
- 时间线跨年跨月可定位；没有标题的日记仍然易读，不反复显示待填写提示。
- 心情流程可仅用键盘完成，日期可达；未选择不等于平稳；失败可重试且不丢草稿。
- 在 260/320/400px 侧栏、主面板、浅深色主题和长中文标签下检查裁切与布局。
- 只为行为风险补测试：焦点保留、草稿保留、保存锁定、失败重试。视觉值用截图检查，不为每条 CSS 写复述测试。
- 本轮没有运行生产测试，因为没有修改生产代码。实际运行时验证只覆盖上述无写入路径。

## 启发式粗评

这是有限证据下的设计判断，不是可访问性认证。

| 项目 | 分数 / 4 | 主要原因 |
|---|---:|---|
| 状态可见 | 2 | 有加载态；保存主要靠禁用和透明度 |

| 用户控制 | 1 | 草稿离开和切换日期策略不足 |
| 一致性 | 2 | 主题变量较好，弹窗和普通控件语言不同 |
| 错误预防 | 2 | 有提交禁用，仍有隐式默认值 |
